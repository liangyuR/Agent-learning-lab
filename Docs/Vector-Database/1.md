# 1. 什么是向量数据库？vector database

向量数据库 是一种专门用于存储、索引和检索由嵌入模型生成的高维向量的数据库。

### 核心特点：

存储对象：不是原始文本、图片，而是它们的 向量表示（一串浮点数，如 [0.23, -0.45, ...]）。这个向量“嵌入”了原始数据的语义特征。
核心操作：不是传统的精确匹配（WHERE name = ‘张三’），而是 相似度搜索（给定一个查询向量，找出最相似的 K 个向量）。

### 关键能力：

支持高维向量（常见 768、1536、4096 维）。

提供高效的近似最近邻（ANN）搜索算法（如 HNSW、IVF），能在百万/十亿级数据中毫秒级返回结果。

通常支持标量过滤（如同时按向量相似度和 “时间 > 2025年” 条件检索）。

常见产品：Milvus、Zilliz Cloud、Pinecone、Weaviate、Qdrant、Chroma、LanceDB 等。

### 简单比喻：

传统数据库：像一本通讯录，按姓名（精确键）查找电话。
向量数据库：像用嗅觉寻找“气味相似”的东西 —— 你给一个橘子，它找出其他闻起来像橘子的水果（语义相似）。

# 2. 在 RAG 上有什么作用？

在 RAG（检索增强生成） 架构中，向量数据库扮演着 外部知识库的检索引擎 这一核心角色。
## RAG 标准流程 vs 向量数据库的作用：

### 离线阶段（准备知识）

你的文档（PDF、网页、FAQ）被切分成小块（Chunks）。
每个块通过嵌入模型变成一个向量。
向量数据库存储这些向量及其对应的原文。

作用：成为大模型的外挂知识库。

### 在线阶段（回答查询）

用户问一个问题（如 “2025年公司的新政策是什么？”）。
同一个嵌入模型将这个问题也转换为向量。
向量数据库接收这个查询向量 → 执行相似度搜索 → 返回最相关的 K 个文档块（及其原文）。
系统将“用户问题 + 检索到的原文块”拼成提示词，送给大模型。

大模型基于这些事实回答，解决幻觉、知识截止日期问题。

# CLI 文本助手测试用例

用于测试是否能正常回复/机械Json语句

## 1. 周报类

### 输入

本周完成了自动充电系统的联调测试，机械臂抓取流程已经跑通，地轨定位误差控制在±5mm以内，但在连续运行8小时后出现两次抓取失败。相机识别整体稳定，不过在强反光场景下识别速度有所下降。下周计划继续优化地轨定位精度，并补充异常重试机制。

### 输出

```json
{
  "summary": "自动充电系统已完成联调测试，核心流程已跑通并达到初步精度要求，但在长时间运行稳定性及特定光照环境下的识别效率仍需改进。",
  "key_points": [
    "自动充电系统联调测试完成，机械臂抓取流程跑通",
    "地轨定位精度控制在±5mm以内",
    "相机识别在常规环境下表现稳定",
    "系统已进行8小时连续运行测试"
  ],
  "risks": [
    "长时间运行（8小时）存在偶发性抓取失败风险",
    "强反光环境会导致相机识别性能下降"
  ],
  "next_actions": [
    "进一步优化地轨定位精度",
    "开发并补充系统异常重试机制"
  ]
}
```

## 3. 需求描述

### 输入

我们需要开发一个内部文档助手，支持导入 Markdown 和 PDF 文档，用户提问后系统可以返回答案、引用来源片段，并给出简短结论。系统需要支持多轮对话、历史上下文保留，以及基础的权限控制。第一期先做 CLI 版本，后续再考虑 Web 化。

### 输出

```json
{
  "summary": "开发一款支持多格式文档（Markdown/PDF）导入、具备多轮对话能力及权限管理的内部文档助手，项目初期优先实现 CLI 版本。",
  "key_points": [
    "支持导入 Markdown 和 PDF 格式的文档",
    "提供问答、引用溯源及简短结论输出功能",
    "支持多轮对话及历史上下文记忆",
    "集成基础权限控制功能",
    "采用分阶段开发，首期目标为 CLI 工具，后续迭代 Web 版本"
  ],
  "risks": [
    "PDF 解析准确度风险：复杂排版或表格可能导致信息提取偏差",
    "对话质量风险：长上下文管理及模型幻觉可能影响回答准确性",
    "权限控制风险：初期设计的权限逻辑能否平滑迁移至 Web 版本",
    "用户体验风险：CLI 版本对非技术人员的操作门槛较高"
  ],
  "next_actions": [
    "技术选型：确定 LLM 模型、向量数据库及 RAG 框架（如 LangChain/LlamaIndex）",
    "文档解析模块开发：实现 PDF 和 Markdown 的文本提取与分段策略",
    "核心功能实现：构建 RAG 流程，包括索引构建、检索与回答生成",
    "CLI 接口开发：设计并实现命令行交互界面与会话持久化逻辑"
  ]
}
```
